# 公文写作本地演示交互设计

## 目标

将现有静态页面完善为无需后端的可演示应用。用户可在浏览器内完成文件与知识库管理、对话生成、文档编辑、版本恢复和下载；刷新页面后状态保持。

## 范围与边界

- 使用 `localStorage` 保存演示数据，不发送网络请求、不接入真实 AI 或文件存储。
- 允许用户选择或拖入本机的 `.pdf`、`.doc`、`.docx` 文件；演示仅保存文件名、类型和选择状态，不读取或上传文件内容。
- “通用写作”和“公文写作”可用；PPT、思维导图、翻译写作继续禁用。
- 已有示例内容作为首次打开时的初始数据。用户操作后的数据覆盖初始数据。

## 数据模型

浏览器保存单一 `demoState`：

- `sourceFiles` 与 `knowledgeFiles`：`id`、`name`、`type`、`selected`。
- `activeTool`：`general` 或 `official`。
- `messages`：用户和助手消息，附带时间和可选的笔记标记。
- `records`：标题、模式、正文、生成时间、版本列表。
- `activeRecordId`：当前打开的记录。

文件选择状态会同步更新页面中的已选来源计数和会话摘要。

## 交互设计

### 来源与知识库

上传区域点击后打开隐藏文件选择器，拖入合法文件同样添加。文件行可切换选择状态，分组标题可全选/取消全选；更多菜单可删除文件。选中的来源可纳入知识库，知识库中的选项可作为引用来源。

### 对话与生成

快捷问题填入输入框。发送后立刻新增用户消息，显示短暂生成状态，再依据输入、当前模式和已选来源生成结构化演示文本，新增助手消息及生成记录。保存回答会生成笔记记录；复制使用 Clipboard API，并在不可用时给出明确提示。

### 文档与版本

打开记录会加载其标题、正文和版本。标题和正文可编辑；任一全文改写工具或自定义修改要求会生成新正文并自动创建版本。历史版本可切换和还原；下载会生成当前正文的 UTF-8 `.txt` 文件。清空、复制全文和目录跳转会执行真实页面操作。

## 错误与反馈

- 无有效文件、重复文件、没有选择来源、空消息和空修改要求均显示具体 Toast。
- 所有异步演示动作有禁用/加载状态，完成后恢复可操作状态。
- 已删除文件和记录从状态中移除，并立即保存。

## 验收

1. 添加 PDF/DOCX 后可勾选、删除、纳入知识库，刷新后仍显示。
2. 发送内容能产生用户消息、助手回复和可打开的生成记录。
3. 文档编辑、全文操作和版本还原会更新内容并在刷新后保留。
4. 下载得到含当前正文的 `.txt` 文件。
5. 禁用工具不可点击；其他主要操作均有可观察的页面结果而非仅 Toast。
