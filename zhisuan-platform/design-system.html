设计原则

本平台的视觉与交互体系为全新原创，不继承任何既有原型或组件库的令牌与范式。核心主张是 结构用墨，语义用色——颜色只表达语义，不做装饰。

结构用墨

骨架全用石墨墨阶，主操作是墨黑实心按钮。去掉全部彩色后，结构与层级仍完全可读。

语义用色

模块不拥有颜色，语义才拥有颜色。消耗在任何模块里都是同一个琥珀色。

成本前置

任何有消耗的动作，在执行之前就让用户看到代价。不存在“提交后才知道花了多少”。

结构墨阶 Ink

界面的一切结构——文本、边框、主操作——只使用这一条墨阶，不引入彩色。

承载面 Surface

页面、卡片、凹陷区与描边。承载面本身不带语义。

语义色组 Semantic

每组四档：soft 底 / base 主 / strong 强调 / line 描边。 同一语义在所有页面、所有图表中恒定同色。

品牌标识色

仅用于品牌标识、当前模块指示条与焦点环。不用于按钮、不用于装饰—— 若主按钮也是彩色，彩色就失去了“这里有事发生”的信号价值。

CommandPalette · 命令面板（⌘K 触发）

交互模型：七条强制约定

核心命题是让「代价」与「状态」在动作发生之前就被看见。以下七条为强制约定，可直接逐条转为测试用例。

  • 预估前置

    所有计费型动作在执行前必须显示预估（CostButton + CostPreviewCard）。预估来源为 Token 银行费率接口，禁止前端估算。

  • 冻结可见

    执行中冻结量与已消耗量分列呈现，不得合并为一个“已用”数字。

  • 结算回执

    动作结束后生成回执，含预估 / 实际 / 偏差三段；偏差超 ±20% 自动转风险色并给解释入口。

  • 撤销窗口

    提交后、进入执行阶段前的短暂窗口内可撤销并全额解冻；窗口期在 StateStrip 上可见倒计时。

  • 数字是一扇门

    任何消耗数字可点击直达回执或明细；全站无死数字。

  • 不可用也是信息

    因额度 / 配额不足而不可操作时，不得单纯置灰；必须显示缺口量、原因与出路。

  • 键盘优先

    ⌘K 命令面板、⌥L 账板、⌥R 回执、Esc 关闭。关键动作不得只能鼠标完成。

数据可视化规范

可视化目标是回答状态问题，不是展示数据量。

堆叠柱 + 均值参考线

柱顶标数值；虚线为均值参考线，使“是否异常”无需心算。

双轨图：Token 柱 + 卡时线

Token 与卡时禁止换算到同一轴，必须双轴并列；朱红虚线为预警阈值。
