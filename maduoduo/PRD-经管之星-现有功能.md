# 经管之星现有功能产品需求文档（PRD）

## 1. Summary

经管之星是一个面向销售经营管理场景的单文件 HTML 原型平台。当前版本已实现首页经营驾驶舱、智能问数、统计汇报、台账管理、系统管理、日志/反馈相关管理入口，以及需求迭代记录等功能，数据以本地模拟数据和浏览器本地状态为主。

本文档基于当前 `index.html` 已实现能力编写，用于说明现有产品范围、用户价值、页面结构、核心交互和后续演进方向。

## 3. Background

### 3.1 背景

销售经营管理人员需要长期处理商业市场、PPL 明细、整体目标等台账数据。传统方式依赖 Excel 汇总、人工筛选、手动制表和人工汇报，效率低，容易出现口径不一致和信息滞后。

经管之星当前版本以单文件 HTML 的形式，先把核心经营管理流程做成可演示、可评审、可快速迭代的交互原型。它不依赖构建工具，不需要启动服务，直接打开 `index.html` 即可查看。

### 3.2 为什么现在做

当前项目需要先统一业务方、产品、研发、测试对系统功能范围的理解。单文件原型能快速表达页面结构、菜单层级、字段展示、问数体验、统计图表和权限管理方式，为后续工程化开发提供参考。

### 3.3 当前实现状态

- 现有主文件：`/Users/florazhang/Desktop/JGStar/Interaction/index.html`
- 当前形态：单文件业务看板，CSS 和 JS 均内联
- 数据来源：本地模拟数据和浏览器 `localStorage`
- 外部依赖：Font Awesome 已内嵌，当前无需 CDN
- 页面访问：直接用浏览器打开 `index.html`
- 校验方式：使用项目内约定的 Node 校验脚本检查 HTML/JS 基础结构

## 4. Objective

### 4.1 产品目标

经管之星现有版本的目标是提供一个清晰、可演示的销售经营管理平台原型，让业务方可以在一个统一入口中查看经营驾驶舱、维护台账、进行智能问数、查看统计报表，并体验基础系统管理能力。

### 4.2 用户目标

- 销管人员可以集中查看和管理台账数据。
- 经营管理人员可以通过首页和统计报表快速了解经营状态。
- 管理人员可以体验用户、角色、菜单、模型、应用配置等后台管理能力。
- 产品和研发团队可以基于原型确认页面结构、交互路径和后续开发范围。

### 4.3 公司目标

- 降低线下 Excel 汇总和人工汇报的沟通成本。
- 建立统一的经营数据入口和经营分析入口。
- 为后续真实后端、数据库、权限体系和 AI 能力接入打基础。

### 4.4 Key Results

| 目标 | 衡量方式 |
|---|---|
| 完成核心功能原型闭环 | 首页、智能问数、统计汇报、台账管理、系统管理页面均可访问 |
| 支持业务评审 | 业务方能基于页面完成菜单、字段、统计口径和交互评审 |
| 支持离线演示 | `index.html` 可在无构建环境下直接打开，核心页面正常展示 |
| 降低研发理解成本 | PRD 与原型页面一一对应，研发能据此拆分后续工程化任务 |
| 支持持续迭代 | 通过备份目录和需求迭代记录保留历史版本和需求变化 |

## 5. Market Segment(s)

### 5.1 主要用户

| 用户 | 主要任务 | 现有功能支持 |

| 销管人员 | 查看和维护商业市场、PPL、目标台账 | 台账管理、导入导出、导入记录、搜索筛选、分页 |
| 经营管理人员 | 查看经营指标、分析达成情况、发现风险 | 首页驾驶舱、统计汇报、智能问数 |

### 5.2 用户约束

- 当前版本是前端原型，不是生产系统。
- 当前数据主要为模拟数据，不代表真实经营数据。
- 当前导入导出以原型交互为主，后续需要真实文件解析和后端接口支持。
- 当前权限主要用于展示和交互验证，后续需要接入真实认证和 RBAC 服务。

## 6. Value Proposition(s)

### 6.1 对销管人员的价值

- 将台账管理从分散 Excel 操作转为统一页面入口。
- 通过搜索、筛选、分页和导出减少人工查找成本。
- 通过导入记录保留台账更新过程，方便追溯。

### 6.2 对经营管理人员的价值

- 首页直接看到核心经营指标和风险提示。
- 统计汇报按整体达成、产品、商解、行业、重点单元拆分，方便快速定位问题。
- 智能问数提供自然语言查询体验，减少对固定报表的依赖。

### 6.3 对管理员的价值

- 可以在同一后台中查看用户、角色、菜单和模型配置能力。
- 可以通过应用配置管理问数开场白、快捷问题、常问设置等体验项。
- 可以通过日志和反馈相关页面查看 AI 问答、用户反馈和范式沉淀方向。

### 6.4 对项目团队的价值

- 单文件原型便于快速修改和演示。
- 业务评审时可以直接围绕页面讨论，而不是只看静态文档。
- 后续工程化时可以按页面、状态、数据源、权限和接口逐步拆分。

## 7. Solution

### 7.1 UX / Prototypes

当前原型采用企业经营管理后台布局：顶部栏、左侧导航、右侧内容区。页面通过 `navigateTo(pageId)` 在单文件内切换，不需要路由框架。

核心导航如下：

| 一级菜单 | 二级菜单 | 页面 ID | 说明 |
|---|---|---|---|
| 首页 | - | `home` | 经营驾驶舱和快捷入口 |
| 智能问数 | - | `ai-qa` | AI 对话、快捷提问、会话记录、反馈和范式入口 |
| 统计汇报 | 整体达成 | `rpt1` | 中国区整体及各经营单元达成 |
| 统计汇报 | 产品分析 | `rpt2` | 产品线维度收入、同比、结构分析 |
| 统计汇报 | 商解专项 | `rpt3` | 商业解决方案专项分析和预警 |
| 统计汇报 | 行业达成 | `rpt4` | 各行业达成及产品分析 |

| 台账管理 | 商业市场 | `ledger-commercial` | 商业市场台账数据列表 |

| 台账管理 | 整体目标 | `ledger-goal` | 经营单元目标台账 |

### 7.2 Key Features

#### 7.2.1 登录和全局布局

现有能力：

- 支持登录页展示。
- 支持账号密码输入和登录校验演示。
- 支持登出后回到登录页。
- 顶部栏展示品牌、消息入口和用户头像。
- 左侧菜单支持一级/二级导航和折叠。
- 支持浅色和深色主题样式。

验收标准：

- 用户可从登录页进入系统。
- 点击头像可看到用户相关入口和登出入口。
- 点击左侧菜单可切换对应页面。
- 折叠菜单不影响页面切换。

#### 7.2.2 首页经营驾驶舱

现有能力：

- 展示欢迎区域和经营驾驶舱模块。
- 展示核心 KPI、经营单元达成、产品结构、行业收入、风险提示、快捷入口等信息。
- 部分卡片可点击跳转到对应统计报表。
- 图表以 HTML/CSS/JS 模拟绘制，不依赖外部图表库。

验收标准：

- 首页打开后展示核心经营概览。
- 点击相关 KPI 或快捷入口可进入对应页面。
- 页面在桌面尺寸下保持清晰可读。

#### 7.2.3 台账管理

现有子页面：

- 商业市场台账
- PPL 明细台账
- 整体目标台账

通用能力：

- 表格展示模拟数据。
- 支持搜索、筛选、排序、分页。
- 支持导入按钮、导出按钮、导入记录按钮、刷新按钮等原型交互。
- 支持导入记录弹窗和分页。
- 支持不同台账使用不同字段结构。

验收标准：

- 三个台账页面均可访问。
- 表格有数据展示，分页可切换。
- 搜索和筛选不会破坏页面结构。
- 导入记录弹窗可打开和关闭。

#### 7.2.4 智能问数

现有能力：

- 支持 AI 问数页面。
- 支持会话列表、开启新对话、上下文菜单等原型交互。
- 支持用户输入问题并展示 AI 回复。
- 支持快捷提问，包括最近提问和收藏。
- 支持 AI 回复卡片展示数据发现、数据表格、数据统计、数据可视化等结构。
- 支持 AI 分析过程展示。
- 支持 Prompt 日志查看。
- 支持用户反馈、回复优化、回复范式相关入口。
- 支持问数与报表上下文联动的演示逻辑。

验收标准：

- 用户可以输入问题并看到模拟回复。
- 快捷问题可以填入或触发提问。
- AI 回复结构清晰，表格和图表区域可见。
- Prompt 日志和反馈相关弹窗可以打开。

#### 7.2.5 统计汇报

现有子页面：

- 整体达成
- 产品分析
- 商解专项
- 行业达成
- 重点单元

通用能力：

- 支持经营数据表格展示。
- 支持筛选条件和联动刷新演示。
- 支持图形化展示，如柱状、环形、趋势、结构图等。
- 支持部分报表导出 Excel、导出图片或导出文本的原型交互。
- 支持报表中的预警提示和分析总结。

验收标准：

- 五个报表页面均可访问。
- 每个页面有明确标题、筛选区、数据区或图表区。
- 导出类按钮触发后不报错。
- 报表内容与页面标题匹配。

#### 7.2.6 系统管理

现有页面：

- 应用配置
- skill 管理
- 用户管理
- 角色管理
- 菜单管理
- 模型配置

现有能力：

- 用户管理展示用户列表、状态和操作入口。
- 角色管理展示角色列表和权限配置入口。
- 菜单管理展示菜单树、路径、权限标识等信息。
- 模型配置展示模型连接信息和测试连接/保存等入口。

验收标准：

- 系统管理下各页面可正常打开。
- 表格、弹窗、开关、按钮交互可用于演示。
- 权限配置弹窗或 tab 切换不影响主页面导航。

#### 7.2.7 日志、反馈和范式能力

现有能力：

- 智能问数内保留会话日志、Prompt 日志、用户反馈、管理员反馈等数据结构。
- 支持回复校对、回复范式、反馈备注等原型交互。
- 支持范式列表、详情、编辑、删除等演示能力。

验收标准：

- 从 AI 问数相关入口可查看日志或反馈弹窗。
- 范式相关列表和详情可以展示。
- 反馈处理类操作能在当前页面完成演示。

#### 7.2.8 需求迭代记录

现有能力：

- 左侧底部有“需求迭代记录”入口。
- 支持新增需求迭代记录。
- 使用 `localStorage.reqIterData` 保存记录。
- 有未读或新增记录时显示红点提示。

验收标准：

- 点击入口可以打开需求迭代记录页面。
- 新增记录后页面可展示该记录。
- 刷新后记录仍可保留在本地浏览器中。

### 7.3 Technology

当前技术形态：

- 单文件：`index.html`
- 无构建工具、无 npm、无打包流程
- CSS 内联，JS 内联
- 页面路由：通过 `navigateTo(pageId)` 控制 `.page-content` 显隐
- 数据状态：通过全局对象和数组维护，如 `tableState`、`ACT`、`CURRENT_USER` 等
- 本地持久化：部分需求迭代记录使用 `localStorage`
- 图表：以 HTML/CSS/Canvas/原生 JS 模拟，不依赖 Chart.js
- 图标：Font Awesome 已内嵌到页面中
- 运行方式：浏览器直接打开

当前项目约束：

- 修改 `index.html` 前需要先备份到 `backup/` 目录。
- 上传云效时需要复制为自包含 HTML 文件。
- 后续工程化前，需要把模拟数据、页面状态、接口、权限、文件导入导出拆分出来。

### 7.4 Assumptions

当前版本基于以下假设：

- 业务方认可先用单文件原型确认功能范围。
- 当前模拟数据足够支持评审页面结构和统计口径。
- 后续会接入真实后端、数据库、鉴权和文件解析能力。
- 智能问数当前以原型交互为主，真实 AI 取数、SQL 执行、模型调用需要后续工程实现。
- 当前权限演示不等于生产级权限控制。
- 当前导入导出主要用于演示，真实 Excel 解析和文件生成需要后端或前端文件库支持。

## 8. Release

### 8.1 当前版本范围

当前版本是可演示原型版本，重点是功能结构完整和页面体验可评审。范围包括：

- 登录和主框架
- 首页经营驾驶舱

### 8.2 下一版本建议

建议下一阶段按“原型到工程化”的顺序推进：

1. 数据层工程化：接入真实后端、数据库和 Excel 导入解析。
2. 权限工程化：接入真实登录、用户、角色、菜单权限和接口鉴权。
3. AI 工程化：接入真实模型配置、台账取数、SQL 生成、分析过程和 Prompt 日志。
4. 报表工程化：统一统计口径，抽象报表接口，支持真实导出。
5. 测试工程化：补充页面回归、导入导出、权限、问数、报表统计测试用例。

### 8.3 不在当前版本范围内

- 真实生产数据接入。
- 真实文件上传到服务器。
- 真实 Excel 解析入库。
- 真实大模型接口调用。
- 生产级 RBAC 权限和数据权限。
- 多用户并发和审计级日志。
- 后端服务部署和数据库迁移。
